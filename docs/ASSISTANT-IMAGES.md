# Assistant image batches

The Assistant accepts up to eight images per message, 20 MiB per image and 40 MiB combined. Picker, paste and drop append to one ordered attachment list. Each image has a preview, full-size link and accessible remove button; the label shows the selected count. The composer uses direct form children and a semantic ul/li preview strip, with no nested divs. Scoped grid rules override the old workspace flex rule without changing other pages.

Normal image previews use browser object URLs. Browser-unreadable formats request a CSRF-checked temporary preview through the existing POST /chat handler with preview=1. These conversions run serially on the client, use the existing Pillow/HEIF decoder, never invoke a model and never save an upload. Removal aborts a pending conversion. Send waits until all previews are ready; an unreadable image must be removed or replaced. Object URLs are released on removal, conversation clear, saved-diary receipt replacement and unload. Attachment binaries are not stored in localStorage.

Repeated multipart image fields reach the existing Gemini call in displayed order. Provider rasters are bounded to 2048 pixels per edge and decoded one at a time to limit RAM; original upload bytes are kept for an explicitly requested diary save. No new service, model, watcher or dependency. New drafts added during a request remain intact. Regenerate retries the complete batch with its original request ID. Existing single-image history remains readable.

Diary saves use the existing hash-deduplicated image store, append every attached image in order to one entry and preserve receipt/idempotency rules. Ordered image_urls receipts keep the sent image previews available after a diary save. Ordinary analysis does not itself write image files; existing user-intent/tool authorization remains unchanged. Calendar imports keep both deterministic extraction passes and show every account-scoped source preview; new numbered previews share the existing 24-hour expiry cleanup, including interrupted-write orphans. Existing one-image drafts remain readable.

Validation: tests/test_assistant_images.py and existing tests/test_assistant_diary.py cover bounded multipart input, authorized batches, rejected files, real HEIC preview conversion without AI/storage, provider image order, calendar passes/previews/expiry, and diary receipts. tests/test_diary_writer.mjs covers ordered multi-image append, same-ID retry, concurrency, conflicts and original single-image behavior. No real diary is written by these tests.

Optional browser regression: run tests/browser_assistant_images.py FIXTURE_DIRECTORY in the existing video-worker Playwright environment. The temporary fixture contains page.html rendered from the real assistant template with a test session, chat.js, chat-page.css, and the deployed static/ asset tree. All chat POSTs are mocked to avoid user data writes. Checks include desktop/mobile dark styles, actual file chooser/paste/drop, removal/URL release, image order, preserved next draft, same-ID retry, serial fallback previews, limits, full-width text below the thumbnails, no horizontal page overflow, no nested composer divs and JS errors. Screenshots are task scratch, not retained backups.
